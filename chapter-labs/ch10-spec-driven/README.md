# Chapter 10 Lab — Specification-Driven Development

**Starting state:** `ch09-plugin-ready`

**Objective:** convert a vague issue into an engineering contract before implementation.

## Deliverables
- `specification.md`
- `verification-matrix.md`
- `traceability.md`

## Workflow
1. State problem, current behavior, and desired behavior.
2. Separate requirements from non-requirements.
3. Record architectural/security constraints.
4. Define acceptance criteria before seeing the implementation.
5. Map Requirement → Plan → Implementation → Verification.
6. Block on unresolved product/security decisions instead of inventing them.

## Verification
A reviewer should be able to determine whether the eventual diff is correct without needing the implementation agent's interpretation of success.
